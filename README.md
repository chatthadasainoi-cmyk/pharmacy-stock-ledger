# สมุดคลังยา

ต้นแบบระบบคลังยาสำหรับร้านยาที่ดูแลโดยเภสัชกรคนเดียว ใช้สแกนบาร์โค้ดที่กล่องหรือแผงยาเพื่อรับเข้า ขาย และดูประวัติว่ายาแต่ละล็อต **เข้าเมื่อไหร่ ขายไปเมื่อไหร่**

ทั้งหมดอยู่ในไฟล์เดียว `index.html` ไม่ต้องติดตั้งหรือ build อะไร

## ทำอะไรได้

- **สแกนได้ 2 แบบ**
  - **EAN-13 / UPC:** บาร์โค้ดเส้นบนยาไทยทั่วไป บอกได้ว่าเป็นยาตัวไหน ส่วน LOT และ EXP กรอกเองตอนรับเข้า
  - **GS1 DataMatrix:** อ่านรหัสยา (01), วันหมดอายุ (17), ล็อต (10) และ serial (21) ให้อัตโนมัติ
- **สแกนด้วยอะไรก็ได้**
  - เครื่องสแกน USB หรือบลูทูธ ยิงได้ทันทีโดยไม่ต้องคลิกช่องก่อน
  - กล้องมือถือหรือเว็บแคม
  - ถ่ายรูปบาร์โค้ดแล้วให้ระบบอ่านจากรูป
- **ขายแบบ FEFO:** ระบบเลือกล็อตที่หมดอายุก่อนให้อัตโนมัติ ไม่ยอมตัดจากล็อตที่หมดอายุแล้ว และแสดงให้เห็นว่าหยิบจากล็อตไหน
- **หน่วยนับหลายระดับ:** เช่น เม็ด / แผง / กล่อง บาร์โค้ดของกล่องกับแผงผูกกับหน่วยต่างกันได้
- **ประวัติทุกการเคลื่อนไหว:** รับเข้า, ยอดยกมา, ขาย, ยกเลิกบิล, ปรับยอด, ตัดทิ้ง พร้อมวันเวลา ล็อต และเลขบิล
  - ยอดคงเหลือคำนวณจากประวัติทั้งหมดเสมอ
  - กรองประวัติตามประเภทยาได้ (ยาอันตราย / ยาควบคุมพิเศษ) เพื่อทำบัญชี ขย.
  - ส่งออกเป็น CSV ได้
- **แจ้งเตือน:** ยาหมดอายุที่ยังค้างในคลัง, ล็อตใกล้หมดอายุ (ตั้งจำนวนวันได้), ยาใกล้หมดตามจุดสั่งซื้อ
- **บาร์โค้ดร้าน:** สร้างรหัสช่วง `20xxxxxxxxxxx` ให้ยาที่ไม่มีบาร์โค้ด แล้วพิมพ์ติดได้
- **สำรองข้อมูล:** ส่งออกและนำเข้าเป็นไฟล์ `.json`

## การเก็บข้อมูล

| ตั้งค่าแบบไหน | ข้อมูลเก็บที่ |
|---|---|
| ใส่ค่า Firebase ใน `config.js` | Cloud Firestore ต้องล็อกอินด้วย Google ซิงก์ทุกเครื่อง และใช้ต่อได้ตอนเน็ตหลุด |
| `config.js` ยังเป็น `firebase: null` | `localStorage` ของเบราว์เซอร์เครื่องนั้น ควรสำรองเป็นไฟล์เป็นประจำ |

### ตั้งค่า Firebase (ทำครั้งเดียว)

1. สร้างโปรเจกต์ที่ [console.firebase.google.com](https://console.firebase.google.com) ไม่ต้องเปิด Google Analytics
2. เปิด **Build → Authentication → Get started** แล้วเปิดใช้ **Google** เป็นวิธีล็อกอิน
3. ไปที่ **Authentication → Settings → Authorized domains** แล้วเพิ่มโดเมนเว็บ เช่น `<ชื่อบัญชี>.github.io`
4. เปิด **Build → Firestore Database → Create database**
   - เลือก location `asia-southeast1` (สิงคโปร์)
   - เลือก production mode
5. ในแท็บ **Rules** วางเนื้อหาจาก `firestore.rules` แก้รายชื่ออีเมลที่ให้เข้าร้านได้ แล้วกด **Publish**
6. ไปที่ **Project settings → Your apps → Web (`</>`)** แล้วลงทะเบียนแอป
7. คัดลอกค่า `firebaseConfig` มาวางแทน `null` ใน `config.js`

ค่าใน `firebaseConfig` เป็นค่าสาธารณะของเว็บแอป ไม่ใช่รหัสลับ ใครจะอ่านหรือเขียนข้อมูลได้ถูกกำหนดโดย `firestore.rules`

แพ็กเกจฟรี (Spark) อ่านได้วันละ 50,000 ครั้งและเขียนได้วันละ 20,000 ครั้ง ร้านยาร้านเดียวใช้ไม่ถึง

ถ้าจะใช้กล้องสด ต้องเปิดผ่าน `https://` หรือ `localhost` เพราะเบราว์เซอร์ไม่อนุญาตกล้องบนหน้า `file://`

## ข้อมูลตัวอย่าง

```bash
node tools/make-sample.mjs sample
```

คำสั่งนี้สร้าง `sample/sample-backup.json` ไว้นำเข้าที่หน้า **ตั้งค่า → นำเข้าไฟล์สำรอง**

ยา ล็อต ราคา และบาร์โค้ดในข้อมูลตัวอย่างเป็นข้อมูลสมมติทั้งหมด บาร์โค้ดใช้ช่วง `20…` ที่สงวนไว้สำหรับใช้ภายในร้าน จึงไม่ชนกับสินค้าจริง ลบออกได้ด้วยปุ่ม "ลบข้อมูลตัวอย่าง"

## โครงสร้างข้อมูล

- `products/<id>`: ชื่อยา, ชื่อสามัญ, ความแรง, ประเภทตามกฎหมาย, หน่วยนับและราคา, บาร์โค้ด → หน่วย, ล็อต (LOT, EXP)
- `moves/<YYYY-MM-DD>`: รายการเคลื่อนไหวของวันนั้น
  - แต่ละรายการมี `type`, `pid`, `lotId`, `qty` (หน่วยเล็กสุด บวกหรือลบ), หน่วยที่ใช้, ราคา, เลขบิล, หมายเหตุ
  - เก็บรวมเป็นวันละเอกสาร เพื่อไม่ให้จำนวนเอกสารในฐานข้อมูลโตเร็วเกินไป
- `meta/settings`: ชื่อร้าน และจำนวนวันที่จะเตือนก่อนหมดอายุ

## ข้อจำกัดของต้นแบบ

- ออกแบบสำหรับผู้ใช้คนเดียว ยังไม่มีระบบบัญชีผู้ใช้หรือสิทธิ์
- ยังไม่ออกรายงาน ขย. ตามแบบฟอร์มทางการ มีแค่ CSV ที่กรองตามประเภทยาได้
- ประเภทยาในข้อมูลตัวอย่างใช้เพื่อสาธิตเท่านั้น ควรตรวจกับทะเบียนตำรับยาจริงก่อนใช้งาน
